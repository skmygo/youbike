誠實的部分

這些我們沒做到，或做不到

  • 誤報率 52%：營運門檻照「F1 最佳」選，高偵測率的代價就是誤報多
  • 滿位事件比較難預測（偵測率 51%）：事件本身少，3,909 起 vs 35,450 起，樣本不平衡
  • 沒有天氣：手上沒有中央氣象署 API key，就算爬到歷史觀測，線上推論時也拿不到即時值與預報——做出來是個永遠 degraded 的特徵，所以誠實地不做
  • 假日是資料驅動偵測的（抓到 18 個平日假期，含春節連假），不是官方行事曆，補班日還沒分出來
  • 線上預測正在暖機：即時快照這次才開始累積，不足 7 天的 lag 用「同站、同星期幾、同時段的上一次實際觀測」橋接，介面上誠實顯示即時資料佔比

工程

它現在就在跑，不是一個 demo

  • 全自動：Dagster 每 10 分鐘爬取 → 物化服務層 → 重算警示 → 推播新升級的站；每 30 分鐘跑一次線上推論。全程無人
  • 推論不進 API 請求路徑：模型結果由排程算好寫 parquet，API 只讀檔——首頁不會因為模型變慢
  • 線上特徵與訓練逐欄對齊：同一套 window SQL，杜絕 training/serving skew
  • 資源紀律：訓練機同時是正式服務主機，重活一律戴 systemd-run 資源罩（4G／400%）；半夜真的被 OOM 殺過一次，做法是縮規模而不是調大上限，抽樣 35%→22%、峰值壓到 1.88G
  • 全部可重現：20 個模型逐一進 MLflow，回測報告與 KPI 模擬隨模型一起版本化上 S3
